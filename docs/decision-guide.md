# Find the first failed step

Begin with what the reader observes. Ask before touching someone's phone, and let them keep control of it. Do not ask for an administrator password, take a photo of their screen, or record personal information in the rehearsal log.

| Observation | Check with the operator | Next useful action |
| --- | --- | --- |
| The reader cannot scan a QR code, or is viewing it on the same phone. | Is a normal descriptive link or readable typed address available? | Use that alternative. Revise a bulletin that contains only a QR image. |
| The typed address does not open. | Does the printed spelling match the approved short address? Does that address currently resolve on the available connection? | Correct the spelling or redirect. If the connection is unavailable, offer the prepared fallback rather than repeating the same instructions. |
| A page opens, but it is a sign-in or control dashboard. | Was a public listener link supplied? Does this provider require listener sign-in, and was that truthfully explained? | Obtain and test the intended listener route. Never share the operator's account or promise that an account requirement can be bypassed. |
| The page shows the wrong church, date or event. | Is this an old bookmark, rehearsal event or stale short-address redirect? | Correct all distributed destinations together; rerun the current-service check. |
| The desired language is absent. | Is that language actually offered for this service and support window? | Correct the advertised offer or provide the already prepared alternative. Do not promise a language the operator cannot supply. |
| The page and language look correct, but no new text arrives. | Has the actual session started? Is input reaching the service? Does the provider require a normal listener start action? | Follow the provider's tested procedure. Record the observed failure and use the fallback if it cannot be restored. |
| Text arrives, but the advertised audio does not. | Is audio supported for this language, and have normal listener controls and device volume been checked? | Use the provider's ordinary instructions. Explain honestly if only text is available; ask what alternative helps. |
| Text is present but hard to read or understand. | Does the selected language and format match what the reader requested? | Ask which format or assistance would help. A network restart does not resolve unreadable text or inaccurate wording. |
| The reader has no usable phone, or does not want this route. | Is the named fallback and assigned helper actually available? | Offer that support without pressure to install, sign in, share a device or disclose an access need. |

Keep technical delivery and language quality separate. A visible test passage proves that content arrived; it does not prove its meaning is correct. Ask a competent language reviewer to assess content in context, using the church's own terminology and service plan.
