# Rehearse the listener entry path

Use an operator, a welcome volunteer and one person who did not prepare the instructions. The last person acts as the reader; they do not need to disclose personal access needs or create a new account for this exercise. Ask the people you intend to serve which formats and language varieties they need, and use their feedback when preparing real instructions.

## Prepare

- Complete the operator handoff: service date, version, actual support window, public route, language choices, helper and fallback.
- Obtain permission for the short test passage. Use material the speaker may share; do not record a real visitor or private conversation.
- Make the public listener route available in the provider's normal way. Do not publish operator credentials, private tokens, Wi-Fi passwords or dashboard URLs on a card.
- Copy the blank log. Use device labels such as `Phone A`; no participant names or full device identifiers are needed.
- Give the reader only the proposed card or digital bulletin for the first attempt. Record prompting honestly if a helper has to intervene.

## Run these six checks

| Check | Reader action | Evidence to record |
| --- | --- | --- |
| Digital link | Open the digital bulletin on the same phone; use the descriptive text link, without scanning its QR image. | The final page identifies the intended church and current service. A link that opens some page is insufficient. |
| Typed address | Type the short address exactly as printed, starting in a fresh ordinary browser tab. | The redirect reaches the same intended service; record any typo or ambiguous character that prevented it. |
| Correct language | Follow the provider's normal instruction for selecting the offered language. | The intended language is available and selected. Record an unavailable language as a failure of the advertised offer. |
| First passage | Have the operator send the permitted test passage through the actual service. | The expected text arrives; if audio is advertised, separately confirm that the advertised audio route works. A competent reviewer handles meaning and language accuracy separately. |
| Help point | Ask the reader to find the help location using only the card. | The assigned helper is findable and knows the service and fallback. An unmanned sign is not a working help point. |
| No-phone fallback | Set the phone aside and ask what support is available. | The offered alternative is present, usable and honestly described. A printed outline does not promise live interpretation. |

The operator may need to pause or end a rehearsal session. Check the provider's own instructions; this pack does not assume that restarting, refreshing or reconnecting restores missed content.

## Fail, correct and retest

Write `PASS`, `FAIL` or `NOT TESTED` for each observed check. For a failure, describe the first specific mismatch, not just “translation broken.” Assign a role to make the correction and record a separate retest row with the updated card version. Keep the failed row; it explains why the card changed.

Examples: the printed short address still redirects to last week's service; the page opens but only an unadvertised language is available; text works but the requested audio never starts.

## When the service plan changes

If the destination, language offer or support window changes, replace the digital bulletin link, printed address and any QR destination together. Repeat the affected entry and first-passage checks. Withdraw an offer that has no working route or fallback. Tell the welcome team which card version remains valid.

Do not call an untested route ready. The release check records the team's decision; it does not guarantee future network or provider availability.
